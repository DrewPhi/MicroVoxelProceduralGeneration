# [FV] Seeded streamed world: FBM landforms, climate biomes and canonical static waterways

## Outcome and scope

Add an opt-in `SeededWorld` recipe/preset that can be explored continuously: the same seed, source version and global coordinates produce the same 6.25 cm voxels regardless of travel, chunk generation order, worker count or cache eviction. Build a complete first visual checkpoint with continents/coasts, mountain ranges, hills, plains, climate-driven surface biomes, connected regional rivers, lakes and oceans. No vegetation in this preset. Preserve Alpine, Regional and Legacy behavior and existing renderer optimizations.

This is a new source for the current near NAADF / distant adaptive raster renderer, not a renderer replacement. Static opaque water is sufficient initially. Live flow, erosion simulation, transparent/refraction rendering, vegetation, caves generated by the new recipe and continent-wide physically correct drainage are subsequent work. Existing edit/volume ownership remains authoritative.

Depends on the contracts in `ARCHITECTURE.md` and master #24; this does not claim completion of renderer gates G3/G4. Split acceptance into **A: renderable seeded-world checkpoint**, **B: streaming/quality acceptance**, and **C: later water simulation**. Finishing A must not imply C is implemented.

## Canonical source and interfaces

Use a separate `world/src/seeded_world.rs` behind `FbmRecipe::SeededWorld`. Keep source and appearance versions explicit. Recommended interface (names may follow existing conventions):

```rust
struct TerrainColumn {
    ground_top: i64,    // exclusive solid top
    visible_top: i64,   // >= ground_top; higher means static water
    ground_surface: Material,
    ground_subsurface: Material,
}
// FbmTerrain::column_cells(global_x_cell, global_z_cell) -> TerrainColumn
// FbmTerrain::ground_height_m(...) is separate from visible height_m(...)
// sample_fields(...) -> climate, SeededBiome, hydrology diagnostics
// Optional water kind/body ID can live in those diagnostics.
```

Compute this once per `WorldColumn`, reusing it for all y queries. `World::material` and column material queries must agree, including edits. Surface material/color, reference extraction, NAADF preparation and adaptive appearance all consume this same sample. Never independently regenerate a biome or water mask in WGSL. CPU canonical samples are uploaded through existing paths.

For checkpoint A, add `Sand`, `Snow` and **nonblocking opaque `Water`** materials as needed. Cells below the ground top retain their bed/soil/rock material; cells in `[ground_top, water_top)` are water; cells above are air. An edit overrides this projection. Grounded movement uses solid collision/ground height, not visible water height. Swimming is deferred; state that limitation in the preset documentation. The canonical water definition remains a separate column field so future fluid state need not be encoded as solid terrain.

Audit material-count arrays, serialization, packed material IDs, shader palettes, ray hits and acceleration summaries. In particular, native column/run shortcuts must not assume that everything under the visible top is soil or stone. Either support explicit runs (rock/soil/bed/water/air) or use the correct general path. Do not silently make water opaque in one renderer and absent in the other.

## Landforms and climate

Use decorrelated salted FBM fields with versioned physical wavelengths, independent of LOD. A useful starting scale hierarchy is continentality at 16–64 km, uplift/range envelopes at 2–12 km, ridged range relief at 0.5–3 km, hills at 100–800 m, and decaying fine relief at 1–64 m. Domain warp is bounded and continuous. Mountains arise inside broad uplift provinces; lowland amplitude falls continuously outside them. Avoid multiplying every terrain location by a mountain recipe or assigning terrain independently by chunk.

Evaluate broad source fields on a **globally anchored, fixed-resolution canonical field lattice**, then interpolate with one specified bounded continuous rule. This interpolant is the source definition, not a camera-dependent approximation. Initial field spacing around 64–128 m and climate spacing around 256 m are tuning candidates, fixed in the source version. Evaluate only a small number of local fine bands per column. Fine detail fades inside channel/lake corridors so it cannot dam or break water continuity.

Climate is a bounded approximation, not a global weather simulation:

- Temperature combines a broad seeded heat field, elevation lapse term and modest maritime influence. A broad heat field avoids an unbounded flat world becoming permanently polar after one latitude crossing.
- Rainfall combines maritime/continentality fields, windward uplift and a rain-shadow estimate from a fixed number of upwind **macro-only** samples (e.g. four taps over 1–8 km). This sampling must not recurse into final terrain or drainage.
- Soil moisture combines rainfall, temperature-related drying, slope/drainage and a bounded riparian contribution. Preserve continuous temperature/moisture fields; classify biome only afterward.
- Warm/dry lowlands yield desert, temperate moderate/wet lowlands plains/grassland, cold lowlands tundra, high/cold terrain snow, and steep exposed terrain rock. Beaches use shoreline and slope. Biome labels are diagnostics; material follows the same physical fields at native columns. No separate random biome tiles or cell-hash speckle.

Record sample seed/coordinates for each expected landform and biome. Avoid a hard-coded origin meadow masquerading as a seeded world. A bounded deterministic spawn search may select a walkable dry column and report its coordinates.

## Bounded, seam-free regional drainage

Checkpoint A deliberately uses a **globally addressed local drainage graph**, not a full watershed solution. Hydrology cache tiles store graph data; they never define its border conditions.

1. Place hydrology nodes on a global coarse lattice, initially about 1 km apart. Derive node elevation/stage, climate and identity only from seed and global node coordinates. Choose the lowest strictly lower neighbor among eight adjacent nodes, using a stable coordinate tie break. No outgoing edge means a sink. Do not select a slightly higher neighbor merely to force drainage.
2. Each node emits at most one downstream edge. Its descriptor has stable endpoint IDs, endpoint water stages, bounded width/depth, a bounded curve and an influence AABB. All incident edges use the same node stage. Interpolated downstream stages cannot increase; quantization may produce level steps. Acyclic edges follow strict decreasing elevation; no query traverses the full downstream chain.
3. Emit a continuous channel on each selected above-sea edge for this first checkpoint. Width is a clamped local rainfall/runoff proxy shared at nodes; it is **not accumulated upstream discharge**. Keep narrow headwaters rather than independently thresholding edges in a way that disconnects the network. Dry biome surroundings may still contain these schematic perennial streams.
4. Sink nodes own bounded endorheic lake basins with one level and a stable body ID. Their radius/influence is strictly bounded relative to graph spacing. Incoming edges meet that same level. Sea-level water fills the canonical below-sea field; edges reaching it meet sea level. Below-sea inland depressions may therefore be inland seas: no hidden unbounded ocean-connectivity flood fill is claimed.
5. Condition terrain around the channel/lake cross section, including a containing bank and bed. Merely painting water over an unmodified FBM mountain is unacceptable. Controlled local cut/fill is allowed and must be bounded; protect the central bed from fine relief. Node/confluence neighborhoods need one shared stage and connected wet footprint. Define deterministic overlap ownership/blending; iteration order must never pick a different surface. Use a simpler straight/segmented channel before adding curvature that introduces uncontrolled crossings.
6. Bound the spatial search from maximum segment length, curve displacement, lake radius and bank support. For example, with one-node-span segments and sufficiently small support, a 5×5 owner-node neighborhood plus a one-node field halo is sufficient; derive and test the actual bound. Spatial bins may reduce hot queries, but cannot truncate candidates silently. AABBs include the entire curve and banks. Adjacent cache tiles generate exactly the same descriptors and boundary samples.

This yields connected local drainage forests and shared river confluences across render/cache boundaries. It intentionally favors local sink lakes and does not guarantee that every river reaches an ocean, realistic continental catchment area, discharge conservation or erosion-shaped terrain. These are documented compromises, not bugs to conceal with fog. If later geography needs long integrated watersheds, introduce a versioned bounded basin hierarchy with explicit shared outlets; do not retrofit independent per-chunk Priority-Flood and expect seam-free global drainage.

## Streaming cost, precision and rendering

Immutable macro/climate/graph pages are keyed by seed, full parameters, source/hydrology/appearance versions and global integer tile coordinates. Derived geometry adds representation settings and edit/water revisions. Use shared immutable page handles, bounded residency and work reservations. Build outside cache locks; deduplicate in-flight builds. Worker/job-local samplers retain page handles and candidate lists so native column loops do not lock the cache for every cell. Eviction must affect cost only, never values. Cold misses cannot trigger unbounded graph searches or synchronous main-thread world generation.

Instrument cold page construction, hot column sampling, candidate counts, cache hit/miss/eviction, source queries and pending memory. The acceptance benchmark must include dense NAADF native columns, not just a sparse terrain preview. Publish maximum neighborhood/work bounds and measured p50/p95/p99 timings; choose exact budgets from actual hardware measurements, not paper claims.

Use i64 native addresses, Euclidean division at negative boundaries and checked arithmetic. Specify a supported practical world extent (initially the existing ±2^32-cell proof domain is already hundreds of thousands of km). Test at that extent; do not claim all i64 coordinates are safely representable as f64 meters. Prefer integer lattice decomposition before local floating-point noise evaluation. GPU coordinates subtract integer origins before f32 conversion. Audit camera movement and adaptive patch IDs for rebasing/overflow; supporting the source alone does not prove the whole viewer works at that distance.

New terrain/water composition must have its own conservative height envelope and source-work accounting. Never let a new enum variant fall through Regional affine/slope/error certificates. Unsupported local proofs return `Uncertified`, with existing explicit unresolved/fallback policy. Measure whether exhaustive fallback is viable and add feature-aware interval bounds where necessary; sampled height extrema are not a proof. A useful first local bound unions canonical macro interpolation corner ranges, bounded fine-band amplitudes and the bed/bank/stage extrema of intersecting feature descriptors. Reject feature influence only using its conservative AABB/support bound. This is a valid interval, but may be loose; tighten using piecewise slope/distance bounds before allowing it to force all visible patches to native resolution.

Expose river/shoreline influence bounds to adaptive refinement. A narrow river can be missed even when terrain height error is small: refine where projected water width is resolvable, and use canonical water-area/coverage filtering at subpixel scale. Do not widen the canonical river to fit a coarse mesh. Preserve the same shore anchors and water stages across LOD. Coarse terrain triangles must not bridge an observable channel or replace wet surface with dry cover. Check actual NAADF/adaptive transitions, not just a top-down map.

## C: later discrete water simulation (design boundary only)

Static generation supplies initial water, not a perpetual source. On activation, materialize a sparse **separate fluid state** with integer mass per native cell (e.g. capacity 256), integer face transfers and fixed ticks. Terrain solidity and fluid occupancy are distinct. Integer mass can be a per-cell property, but visible water geometry must remain on the native voxel grid; do not introduce sub-voxel surface heights. LOD never changes mass or simulation cells.

Use an active frontier and two-phase updates: read tick-N masses, propose downward/lateral face fluxes, resolve each face once with deterministic endpoint ownership, limit outgoing totals and receiving capacity, then apply transfers to tick N+1. Integer remainder allocation and tie breaks are specified, independent of thread scheduling. Wake neighbors on changes; sleep stable regions only after no possible local transfer and a documented settling window. Recheck boundary faces on wake. Start with gravity/equalization, not an unvalidated pressure model.

For unloaded boundaries, the initial safe policy is an impermeable simulation boundary: no mass is sent into an absent chunk. Persist dormant mass and active-boundary metadata; loading both sides resumes exchange. Do not claim loading-order-independent elapsed physics under this policy: generation is order-independent, simulation is deterministic for a fixed activation schedule. Later asynchronous boundary flux requires a persistent exactly-once transfer ledger, not water deletion or implicit regeneration.

Maintain `initial mass + explicit additions - explicit removals = resident + dormant + in-flight mass`. Ocean reservoirs, rain and drains require explicit separately counted sources/sinks; never duplicate infinite ocean water by reactivating generated columns. Terrain edits displace water through a deterministic bounded transaction or retain pending displaced mass. Save changed dry cells as tombstones so regeneration cannot refill drained water. Save ticks, fluid schema/version, sparse masses, sources/sinks and boundary state atomically with affected terrain edits. Visual cache revisions are independent from the fixed simulation tick.

Before enabling live fluids, test sealed-box conservation, cross-chunk transfers, sleep/wake, unload/reload, edits displacing water, save/restart and worker-order replay. Keep this phase out of checkpoint A's implementation scope.

## Legacy reference policy and research

**G (greenfield)** for new geography, climate and hydrology. **R/B** for existing `frontier/world/src/{terrain,alpine,lib,summary,affine_bounds,visual_source}.rs`, `frontier/renderer/src/{adaptive_geometry,appearance_map,native_stream}.rs` and `renderer/src/naadf/` at baseline `287b356`: interface inspection and matched regression only; preserve current optimizations. Historical `main`, `engine-overhaul`, `DrewsAnalyticRendering` and `continuous-terrain` remain read-only ideas/regression references. No scheduler, fitting pipeline or whole-source transplant. Any future selective port needs exact path/commit, license, equality tests and profiling.

Research informs the tradeoffs; no external implementation is copied:

- [Génevaux et al., terrain generation using hydrology (2013)](https://doi.org/10.1145/2461912.2461996): river graphs can constrain terrain through procedural patches/carving; its input-domain construction is not proof of unbounded local generation.
- [Barnes et al., Priority-Flood (2014)](https://rbarnes.org/sci/2014_barnes_depressions_published.pdf) and [reference implementation](https://github.com/r-barnes/richdem/blob/master/include/richdem/depressions/Barnes2014.hpp): depression filling depends on domain outlets. Use only inside explicitly bounded future basins, not arbitrary independently generated chunks.
- [Davis, plate-local river generation (2026 preprint)](https://arxiv.org/abs/2610.00301) and [author's toy implementation](https://github.com/Davismk3/plate-local-river-generation): relevant bounded lazy-region alternative. It constrains rivers to their plate with a border margin; it does not establish unrestricted cross-plate drainage or transferable runtime costs. Treat it as a possible later basin design, not a prerequisite or production performance claim.
