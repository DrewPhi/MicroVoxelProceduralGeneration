# Native / heightfield ownership checkpoint

**Status:** proposed next fixture, not implemented or passed. The current FBM rings and native FBM crop remain separate experiments; neither is a handoff. This checkpoint is for the early ownership smoke gate (FV23/FV31), before selecting clipmaps or CDLOD.

## Why this is the next gate

Geometry clipmaps cache nested, viewer-centered regular grids and morph adjacent heightfield levels. Their source model is explicitly a 2D elevation image / height field, so the method does not itself represent caves, overhangs, bridges, or edits away from one surface ([Losasso & Hoppe 2004](https://hhoppe.com/geomclipmap.pdf), [Asirvatham & Hoppe 2005](https://hhoppe.com/gpugcm.pdf)). The later GPU version demonstrates the value of incremental grids and GPU-side terrain work, not a voxel/heightfield ownership solution. For voxel LOD, transition cells can close cracks between two sampled voxel resolutions, but that does not certify a boundary against a separately generated heightfield ([Lengyel 2010, *The Transvoxel Algorithm*](https://transvoxel.org/)). A recent matched multi-layer terrain study likewise finds that methods which look interchangeable top-down can lose coverage or walls at eye-level views ([Malyshau 2026](https://arxiv.org/abs/2608.17390)).

At baseline commit `9550ed1`, `terrain.rs` was fixed-center and surface-only over `±2048 m`, using empirical box-filter samples; `native_fbm.rs` was a startup-only 8×8 m crop. The moving surface worker now under development changes the first point, but still does not establish native ownership or join the proxy to native geometry. `mesh.rs` has a one-cell sampling halo for an isolated crop, but callers must still prove the crop boundary does not invent faces. Do not infer seamlessness from either image or from these isolated checks.

## Fixture contract

Use one deterministic canonical world/revision and a moving camera. Start with the existing seeded FBM source for the broad surface, and the existing native mountain/cave/bridge/edit fixture for topology. Make a **64 m × 64 m** native ownership window around the camera, initially frozen for the ownership oracle, then move it with hysteresis and incremental column/chunk updates. It is a finite test window, not a world-coverage claim. At 0.0625 m per cell this is 1024 × 1024 columns; rebuilding all of those for every 6.25 cm camera step is not an acceptable implied plan. The native path must enumerate solid height spans / exposed faces from column snapshots and sparse volume overrides; do not allocate or resample a dense vertical prism for ordinary heightfield columns. Caves, bridge parts, and edits use canonical voxel occupancy and override the heightfield-safe classification.

For a 1920×1080 pinhole view with 60° vertical FOV, vertical focal length is `1080/(2 tan 30°) ≈ 935 px`; a front-facing 0.0625 m block projects to about `58.4 / d` pixels at distance `d` metres. Thus a block is about 2 px at 29.2 m and 1 px at 58.4 m. These are face-on estimates, not universal visibility guarantees: use actual projected face bounds for grazing views and silhouette edges. Fixture cameras must inspect native blocks inside 29 m, the full ownership boundary, and motion across it. Record this calculation and actual output resolution in captures.

At each world region, choose exactly one display owner per ray/surface interval:

1. **Native volume owns** cells/regions that are not proven heightfield-safe: cave mouths and interiors, bridges, overhangs, non-top edits, and any multi-interval vertical column. It also owns the near voxel-resolvable ground according to the view-dependent threshold. A finite native fixture edge is explicitly uncovered unless its neighbor halo proves the adjacent canonical material; never close a crop with a solid cap.
2. **Heightfield proxy owns** only the remaining single-valued, unedited surface intervals. It is absent over native-owned footprints at every proxy level. Its coarse samples must derive from the same canonical source and preserve a measured geometric-error bound; filtered FBM averages alone are not such a bound.
3. **Boundary rule:** build the boundary from canonical integer columns and shared endpoint positions. Culling and visibility masks must partition ownership (no two independent surfaces fighting for the same ray and no uncovered ray). Where proxy triangles meet the native top, constrain boundary samples to the quantized canonical tops; do not move or smooth native voxel identity. Subpixel fades may address appearance only after the depth/owner oracle passes; they cannot create missing occupancy or hide a cave cap.

Initially keep the native/proxy boundary fixed in canonical coordinates while cameras cross it, so the test measures geometry ownership separately from camera-dependent LOD. Then enable moving-window recentering with hysteresis. The one-cell neighborhood is sufficient for face culling only; heightfield classification and volume ownership must be available beyond it wherever proxy levels are visible.

## Pass/fail evidence

- Compare each captured ray against `World::material` / exact native DDA at the same seed, revision, camera and pixel. Require **zero** phantom solid hits over cave air or bridge undersides, zero ownership gaps over canonical solid, and no false crop caps at the native window edge. For valid heightfield-owned pixels, report the proxy's geometric/depth deviation against the native ray and enforce a separately declared screen-space tolerance; exact depth equality is only required where native geometry owns the ray.
- Report native owner, proxy owner, uncovered pixels and double-owned pixels separately. Test ground, cave mouth/interior, bridge underside, an added/removed voxel, an edit spanning the boundary, straight movement, stop/resume, turn and teleport readiness.
- For pixels whose reference native face projects to ≥2 px, require the native block silhouette and depth to match the exact voxel oracle. Also report silhouette displacement in pixels, depth disagreement, color/normal discontinuity and temporal changes through the boundary. Set a separate stated tolerance for subpixel proxy geometry; do not call cell spacing itself an error bound.
- Verify canonical cell/material queries remain bit-for-bit identical before, during and after representation changes. Test negative coordinates and a far local origin.
- Record seed/source revision, camera route and speed, hardware, 1920×1080 output, FOV, representation settings, owner counts, generated/uploaded bytes, and CPU/GPU frame p50/p95/p99. This is a correctness gate, not a 60 FPS claim or a clipmap-vs-CDLOD result.

**Exit criterion:** pass the fixed-boundary ownership/depth oracle before claiming a native-to-heightfield handoff. Pass again with recentering and motion before extending the distance or claiming continuous coverage. A finite fixture may demonstrate a local handoff only; multi-mile topology-preserving coverage remains a separate gate.
