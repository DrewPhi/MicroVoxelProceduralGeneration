# Published quadratic super-spline targeted implementation

Source: Rössl, Zeilfelder, Nürnberger, Seidel, VIS 2003, sections 2–3 (precursor to TVCG 2004). Author-uploaded full paper read at https://www.researchgate.net/publication/4046792_Visualization_of_volume_data_with_quadratic_super_splines ; DOI https://doi.org/10.1109/VISUAL.2003.1250399 . Mathematical equations implemented independently; no copied software or figures.

`tools/quadratic_spline.py`: type-6 subdivision (6 face pyramids × 4 edge tetrahedra), exact published seven-stage BB control rules. Blue edge controls average four incident center samples; red corners average eight; green face diagonal controls average incident blue edges; yellow face centers average opposite greens; white corner-center controls combine two greens minus half corner+edge; black face-center-to-cube-center controls average four whites; magenta center is sum black/3 - sum white/8. 65 unique controls. Convert using barycentric congruence to monomial coefficients, no learned loss or runtime blending. Affine/mixed quadratics reproduced; pure square terms generally have approximation bias. C0 across all joins, C1 on cube faces; no claim of global C1 across all internal tetrahedra.

`fbm_points` Rust binary exports sparse f64 global density queries from the original authoring field. Shared stencil uses one-cell halo in every direction. `tools/test_spline_boundary.py` targets the exact old two patches [Y,Z,X] = [0,0,3], [1,0,3]. Crop 8x16x8 m, native 128x256x128 XYZ, 4,194,304 native centers. Inputs need original ignored density/model files. It tests sample spacings 8,4,2,1m and exports independent new models. It is intentionally tied to that fixture, not a general world fitter.

Native errors: old min-of-five 29,198 (0.6961%); spline 8m 380,416 (9.0698%), 4m 307,097 (7.3218%), 2m 127,308 (3.0353%), 1m 36,669 (0.8743%). All four remove the original face's 1,027/16,384 sign disagreements completely, including f32 coefficient evaluation. f64 max face jump <= 1.2e-15; f32 <= 9.6e-7 density units, not meters. Construction + exhaustive checks ~4 seconds. No automatic default-world replacement.

1m model has 1,024 cubes, 24,576 quadratic pieces: expanded GPU coefficient bytes 1,179,648; raw 10*f32 coefficients 983,040 bytes. Stencil values alone would be 7,200 B in f32; this is a representation opportunity, NOT the current renderer's resident memory. GPU currently stores expanded coefficients. Old cropped two-patch model 480 B GPU. Do not claim equal compression or better fidelity. This direct reconstruction is a new representation test, not continuity-constrained refitting of the old coefficients.

New Scene schema representation `quadratic-super-spline-24`, solid `Q>0`, n=24. Same coefficient layout and local normalization. `tetrahedra.rs` static barycentric table matches Python TETS/BARY; WGSL matching table. O(1) piece selection via dominant absolute axis then dominant remaining axis. Continuous rendering traverses regular cubes and ordered tetrahedral intervals, solves one quadratic per interval. f64 reference brute-forces all tetrahedra independently and checks barycentric containment. Exact voxel center queries choose the center's tetrahedron. Conservative skip M is max gradient margin across all pieces in a cube; ray skips clip at tetrahedron exits. Thus neighboring pieces cannot invalidate a center-envelope bound. GPU shader USE_SPLINE constant specialized at load so old backend compiles out spline code. No terrain triangle geometry.

Validation: mathematical self-test mixed-term reproduction, shared internal face equality, adjacent cube value+gradient equality, 10k locator samples. Rust tests add 10k barycentric containment checks and continuous/native plane hit checks. All 22 Rust tests pass (6 analytic, 7 authoring, 7 duplicate exporter, 2 sparse exporter). Five scene cameras × three modes ×80 sparse rays =1,200 f64/GPU comparisons, zero mismatches; accelerated/reference voxel images pixel-identical in all five views (384,000 pixels). Software Vulkan only. Records `output/fit-spline-boundary/1m/viewer-validation.json`. Default scene untouched; inspect with `./analytic --scene output/fit-spline-boundary/1m/terrain.json`.
